# W2-01 synthetic database and migration runbook

Scope: the PostgreSQL schema/repository foundation in this repository. This is not a production provisioning or payroll-release procedure.

## Reproduce the verified local slice

From F:\Codex\Projects\Pay Slip, use the already installed dependencies and retained PostgreSQL 18.6 binaries:

```powershell
npm run test:db
npm run test:unit -- --run packages/attendance-domain/test packages/payroll-domain/test
npm run typecheck
```

The first command invokes scripts/windows/test-database.ps1 -Mode Green. It creates a unique stopped-after-use cluster under .tmp/PAY-W2-01/cluster, binds only 127.0.0.1:55432, uses database payslip_w2_01_synthetic, generates one-run credentials in memory, validates/generates Prisma, applies the migration and runs the restricted-role tests. Ambient DATABASE_URL cannot choose the target. An occupied port stops startup; never kill its owner or select a different port silently.

Tests require this harness. Running the database specs alone without PAYSLIP_TEST_DATABASE_URL deliberately fails closed; RED mode is historical pre-schema evidence and is not a normal post-implementation command.

The migration owner creates extensions/tables/triggers. The separate payslip_app role has no superuser, BYPASSRLS, database/schema ownership, CREATE, TRUNCATE or trigger-administration privilege. The runner grants DML only after migration, then revokes UPDATE/DELETE for the listed append-only tables. Provisioning another environment must reproduce these grants with its own reviewed role contract; this test role setup is not automatic production provisioning.

## Schema authority and boundaries

prisma/schema.prisma declares all 36 model columns and ordinary unique keys. The reviewed SQL migration additionally owns composite foreign keys, check/exclusion constraints, lookup indexes and concurrency triggers. Integration tests compare every declared column type/nullability with the real database and query through the generated Prisma adapter. Do not use prisma db push or an unchecked autogenerated migration to replace the SQL-only invariants.

Repositories use parameterized pg queries on an explicit PoolClient transaction; the Prisma client is available at the server boundary. VND is BIGINT in PostgreSQL and returned by pg as decimal text, including values above JavaScript's safe-integer boundary. Canonical payloads retain exact UTF-8 text; SHA-256 checks never depend on jsonb key formatting. Input/result archives, calculator artifact/version, canonicalization version and result schema version are stored with each payroll employee.

W2 only admits synthetic rule drafts and synthetic pay runs. A synthetic finalized row tests persistence invariants; it does not change payroll-domain finalizable:false or authorize payment. W3-03/W4 own authenticated approvals, complete domain-to-storage orchestration and calculation-result reconciliation. W6 owns PDF creation, destination freshness, sending and worker execution. The future trusted legal import must validate sealed sources/signatures before a reviewed migration permits production release. Do not lift the draft/synthetic checks as a shortcut.

Version records that are append-only use explicit finite effective periods and adjacent successors; replacing an already unbounded version requires a future reviewed close/supersession operation. Compensation/destination rows referenced by payroll/delivery cannot be edited or deleted. History correction adds new records.

## Rollback and cleanup

Before acceptance the initial migration was replayed only into fresh synthetic clusters. After this commit, do not edit an applied migration in place. A future schema change uses a new forward migration, a reviewed backup/restore plan and a new disposable rehearsal.

There is no destructive down migration. If a synthetic rehearsal fails, retain its diagnostics and stopped cluster, correct only the authorized source, and run a fresh unique cluster. Never drop or reset an existing database to get GREEN.

The runner stops its exact pg_ctl-owned cluster in finally and records listener/PID-file absence in ops/evidence/PAY-W2-01-runtime.json. Normal success and failure cleanup have direct receipts. Forced termination/host crash recovery has not been rehearsed. If the host forcibly terminates the runner, inspect only the exact cluster path from its receipt/log and its postmaster PID; after verifying that PID belongs to this project's postgres executable, stop that exact cluster with pg_ctl -D <verified-owned-cluster> -w -t 20 stop -m fast. Recheck 127.0.0.1:55432 and the PID file. Do not stop unrelated PostgreSQL processes on this machine.

Retain ignored portable binaries, archive, stopped synthetic clusters and logs. No Windows service, PATH, existing database, credentials file, real data, provider or public listener was changed. No push was performed.

## Setup provenance and measured failures

- PostgreSQL archive: official EDB selector fileid=1260488; final URL https://get.enterprisedb.com/postgresql/postgresql-18.6-3-windows-x64-binaries.zip.
- Downloaded 344414106 bytes; SHA-256 59F8CE701C63C2ED623C665A5E51B3EF6F2E37CCF837B68FFEED0742D0AE6ABD. This local checksum is reproducibility evidence, not a vendor signature.
- Expanded archive: 916557732 bytes; executable version 18.6.
- Prisma CLI/client/adapter 7.10.0; pg 8.23.0; @types/pg 8.23.1. CLI latest metadata was an RC, so the common verified stable release was pinned.
- initdb --pwfile=- failed because '-' was interpreted as a filename. Exact PostgreSQL REL_18_6 src/common/sprompt.c established the child-only OSTYPE=msys stdin route used with --pwprompt. No password file or global environment change.
- pg_ctl initially inherited captured pipe handles and the wrapper timed out despite a healthy server. Setting only pg_ctl stdio to ignore removed that failure; finally cleanup stopped the first cluster.
- Expanded TDD found missing canonical input/result archives; the migration and schema now store/check both before acceptance.
